# CLAUDE.md — CBAM Borrower Screening Panel

Portfolio tool by Musharraf Hassan. Open this repo in Claude Code and say "Read CLAUDE.md, start Task 0." Work in order. Every task ends with a test or a check; do not move on if it fails.

## 1. What we are building

A screening tool for bank risk teams. Goal: an analyst goes from "here is our borrower list" to "here is who we need to talk to before the February 2027 certificate window" in under an hour, without reading the CBAM regulation.

A local web app (Streamlit) where a bank uploads a borrower table and gets back, per borrower and for the portfolio:

- CBAM tier (0 to 4)
- estimated certificate cost per year, 2026 to 2035, under three carbon-price scenarios and two rule branches
- materiality band (L, ML, M, MH, H) from cost divided by EBITDA
- 2027 liquidity shock
- flags (no declarant status, default emission values only, low pass-through, supplier concentration)
- portfolio roll-up and comparison with any existing transition rating the bank supplies
- a "what to ask this client" question set per borrower, generated from its flags
- csv export of flagged borrowers for the credit file and a one-page summary for the risk committee

Demo runs on a synthetic portfolio of 300 Dutch borrowers whose sector mix matches ABN AMRO's disclosed corporate lending by industry (Annual Report 2025). The word SYNTHETIC appears on every demo screen.

Framing: GARP SCR concepts. Policy transition risk, credit and liquidity transmission channels, NGFS scenario analysis, integration into risk appetite and client due diligence.

## 2. Hard rules

- Rules, thresholds, prices and emission factors live in config/*.yaml with a source and a status (adopted | proposal) on every entry. Never hard-code them in src/.
- No real borrower data anywhere. Demo data is generated by src/synth.py and labelled synthetic.
- Bank figures used for the sector mix are "disclosed gross carrying amount, 31 Dec 2025, ABN AMRO Annual Report 2025."
- The July 2026 ETS free-allocation proposal and the 2028 downstream extension are proposals. Label as such in UI, code comments and docs.
- Python 3.11, pandas, pyyaml, streamlit, plotly, pytest. No notebooks in src/.
- Docs in plain English. No em dashes.
- If a source cannot be fetched, write TODO with the exact document needed and stop. Do not invent numbers.

## 3. Sources (record in data/SOURCES.md with URL and date)

1. Regulation (EU) 2023/956, Annex I goods and CN codes; free-allocation phase-out 2026 to 2034.
2. CBAM Simplification Regulation, Oct 2025: 50 t/year threshold (not electricity, hydrogen); certificate sales from 1 Feb 2027; 2026 certificates priced at quarterly average 2026 ETS; declaration and surrender by 30 Sep of following year.
3. Commission implementing/delegated acts, 17 Dec 2025: default embedded emission values by CN code; certificate price method.
4. Commission proposal Dec 2025: downstream extension to steel and aluminium intensive products from 2028.
5. Commission proposal 17 Jul 2026: slower free-allocation phase-out for CBAM sectors to 2038.
6. Exempt origins: Iceland, Liechtenstein, Norway, Switzerland, plus listed territories.
7. NGFS Scenario Explorer Phase V, EU carbon price: Net Zero 2050, Delayed Transition, Current Policies.
8. Eurostat Comext, NL extra-EU imports by CN8, 2023 to 2025, tonnes (for sector default import intensities).
9. CBS StatLine input-output tables (for pass-through shares to agriculture, construction, food).
10. ABN AMRO Annual Report 2025, corporate loans by industry (~pp. 235 to 236), for the synthetic sector mix.
11. ECB Guide on climate-related and environmental risks, 2020 (for KRI and due-diligence mapping).

## 5. Input schema (template_borrowers.csv)

Required: borrower_id, name, nace_code, country, exposure_eur, turnover_eur, ebitda_eur. Optional: import_t_steel, import_t_aluminium, import_t_cement, import_t_fertiliser, import_t_hydrogen, import_mwh_electricity, top_supplier_country, share_top_supplier, declarant_status (yes|no|unknown), supplier_data (verified|default|unknown), pass_through (high|medium|low|unknown), bank_transition_rating (L|ML|M|MH|H), working_capital_eur. Missing optional fields are filled from nace_tiers.yaml sector defaults and the row is marked estimated = True.

## 6. Logic

Tier decision tree (tiering.py):

- Tier 1: NACE in producer list (24, 23.5, 20.15, 35.11, hydrogen). Loses free allocation.
- Tier 2: imports any CBAM good from a non-exempt, non-EU origin. Direct obligation.
- Tier 3: NACE in downstream-extension list and no direct import. Applies only under the extension branch.
- Tier 4: NACE with material CBAM-good input share (CBS IO tables) and no direct import.
- Tier 0: none of the above. Precedence: 2 over 1 over 3 over 4.

Threshold (cost.py): total CBAM tonnes per year < 50 -> obligation 0, flag MONITOR. Electricity and hydrogen excluded from the threshold test.

Cost (cost.py), per borrower, year, scenario, branch: cost = sum over goods of tonnes * emission_factor * ets_price[scenario, year] * (1 - free_alloc[branch, year]). emission_factor = verified value if supplier_data == verified else default from config. Tier 1: lost allowance value = production tonnes * factor * price * (free_alloc[year-1] - free_alloc[year]); if production unknown, use turnover-based sector intensity and mark estimated. Tier 4: cost = input_share * upstream sector cost uplift, derived from Tier 2 sector results. Tier 3: as Tier 2 but only when branch == extension.

Materiality (thresholds.yaml): ratio = cost / ebitda. Default bands: <1% L, 1 to 3% ML, 3 to 6% M, 6 to 12% MH, >12% H. These are my assumptions; the UI says so.

Liquidity (liquidity.py): 2026 obligation is paid between Feb and Sep 2027 in one block; from 2027 quarterly. Output cash-out as share of working capital where supplied.

Flags (flags.py): NO_DECLARANT (tier 2, above threshold, status != yes), DEFAULT_VALUES (supplier_data != verified), LOW_PASS_THROUGH, SUPPLIER_CONCENTRATION (share_top_supplier > 0.6 and non-EU), ESTIMATED_INPUTS, RATING_GAP (cbam band at least two bands above bank_transition_rating).

Portfolio (portfolio.py): exposure by tier, by band, by scenario and branch; top 20 by ratio; total exposure carrying RATING_GAP.

## 7. Tasks

Task 0: scaffold repo, requirements, pytest, empty configs with commented schemas. Commit.
Task 1: fill cbam_rules.yaml from sources 1, 2, 4, 5, 6. Test: both branches reach zero free allocation at their end year; exempt origins present.
Task 2: fill emission_defaults.yaml from source 3 with data-quality score. Test: every CN group in cbam_rules has a factor.
Task 3: fill scenarios.yaml from source 7, annual 2026 to 2035, interpolated if needed and stated. Test: Net Zero > Delayed > Current from 2030.
Task 4: I hand-write nace_tiers.yaml. Then write tiering.py. Test: fixture rows for each tier and the precedence rule.
Task 5: schema.py with pydantic validation and sector-default filling. Test: a row with only required fields validates and is marked estimated.
Task 6: cost.py. Test with hand example: 1,000 t steel, 1.9 tCO2/t, price 80, free_alloc 0.975 -> 3,800 EUR. Add examples above and below the 50 t threshold.
Task 7: liquidity.py, flags.py and questions.py (maps each flag to one or two plain-English due-diligence questions, stored in config/questions.yaml) with tests.
Task 8: synth.py. Read data/abn_sector_mix.csv and generate 300 borrowers whose exposure shares by NACE match it. Realistic turnover and EBITDA margins by sector from CBS, import volumes from sector intensities, random declarant status and supplier data. Test: sector shares within 2% of target.
Task 9: portfolio.py roll-ups. Test on the synthetic set.
Task 10: app.py. Design for a risk analyst, not a developer. Pages:

- Upload: download template button; upload csv; validation report in plain English (rows accepted, rows rejected and why, which optional fields were filled from sector defaults); reconciliation line at top: total exposure uploaded = total exposure shown. "Load synthetic demo" button with SYNTHETIC banner.
- Portfolio: heatmap of exposure by tier x materiality band; scenario and branch dropdowns with sensible defaults (Delayed Transition, current rules); batch toggle that runs all scenarios and branches and shows best and worst case per tier; sum of exposure carrying RATING_GAP; "what changed vs your own rating" table.
- Borrowers: sortable, filterable table with plain-language tier labels ("Makes CBAM goods in the EU", "Imports CBAM goods", "May be caught from 2028", "Pays via input prices", "Not affected"), band, 2027 cash-out, flags as chips; csv download of the filtered list.
- Borrower detail: cost path chart 2026 to 2035 for all three scenarios; 2027 liquidity chart; "why this rating" box showing the formula with the borrower's own numbers plugged in; "what to ask this client" box listing the due-diligence questions generated from its flags (declarant status, supplier emissions data, pass-through, supplier country concentration, import volume confirmation).
- Summary: one-page export (pdf or html) for a risk committee: portfolio totals, top 20 borrowers, flags count, scenario range, method note, synthetic/real data label.
- Methodology: rendered from docs/METHODOLOGY.md, written for a risk manager.

Rule: the UI never shows a number that cannot be traced to a config entry or an uploaded field.

Task 11: METHODOLOGY.md: purpose, rule summary with sources, formulas, assumptions with status, data-quality scoring, limitations, how to verify each output. Then review it as a sceptical bank risk manager and list unsupported claims.
Task 12: README with screenshot, how to run, disclaimer. Deploy to Streamlit Community Cloud. I add the link to my portfolio site.

## 8. Definition of done

- pytest green, including the hand examples.
- App runs from `streamlit run src/app.py` with synthetic data and with the template csv.
- A test user with only the seven required columns gets a full result with estimated flags, no errors.
- Changing a date, threshold or price in config changes the output without touching src/.
- Each borrower page shows its questions box and its formula box.
- Every number shown in the UI traces to a config entry with a source.
- Methodology page has no unsourced numeric claim.
- README states: synthetic data, sector-level defaults, proposals labelled, not affiliated with any bank.

## 9. Do not

- Invent prices, factors or volumes.
- Use or imply real borrower data.
- Present outputs as any bank's actual exposure.
- Build the UI before the cost engine tests pass.
- Use tier numbers or code names in the UI where a plain-language label exists.
